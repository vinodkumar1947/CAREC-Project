# Choosing and Writing a Good First Issue

Status: Draft
Owner: Documentation Workstream
Last Updated: 2026-08-23
Related Issues: CARE-043 through CARE-046
Related ADRs: TBD

A good first issue must contain a clear goal, essential background, exact deliverable, relevant files/folders, objective acceptance criteria, testing instructions, estimated complexity, hardware requirement, and mentor/owner. It should fit one focused PR and avoid unresolved architecture decisions.

Avoid “Research ROS.” Prefer: “Create a ROS 2 node that publishes simulated ultrasonic range measurements at 10 Hz, with configurable range/noise, message and launch tests, and setup documentation.” Maintainers should reserve several documentation, test, simulation-data, and interface-mock tasks for newcomers and respond promptly to questions.
