# First Contribution

Every new team member begins with a documentation-only practice pull request. This teaches the complete workflow without risking runtime code.

## Exercise

1. Accept the assigned onboarding issue.
2. Clone the repository.
3. Create `docs/contributors/introductions/<github-name>.md`.
4. Include your interests, current skills, and what you want to learn. Do not include private contact or health information.
5. Create a branch named `docs/<issue-number>-<github-name>`.
6. Commit and push the branch.
7. Open a pull request and link the issue.
8. Respond to at least one review comment.
9. Confirm automated checks pass.
10. Wait for the maintainer to squash-merge it.

## Help is expected

Ask questions on the issue so that answers remain available across time zones. A failed check is information, not a failure by the contributor.

After onboarding, select an issue labeled `good first simulation`, `documentation`, `scenario`, or `tooling` before taking safety or velocity-control work.
