Before the meeting, contributors update issues with evidence and blockers; leads prepare Ready work. During the meeting use the [template](../10-meetings/meeting-template.md): 7:00–7:15 introductions/updates, 7:15–7:30 vision/architecture/priorities, 7:30–7:45 assignments/technical discussion, and 7:45–8:00 blockers/questions/next steps.

Each engineer should leave with one clearly defined task, GitHub issue, owner, acceptance criteria, and expected deliverable. Afterward, record decisions as ADRs when needed and update the Project—not a separate private tracker.
